# 柠萌旅行记 Agent 工作台：制作端与管理端整合优化交互方案

版本：V2.0  
定位：基于完整生产流程、管理端治理需求与富内容节点画布参考，重新收敛产品信息架构和关键交互。

## 1. 结论

产品采用“双工作区、同一真相层”的结构：

- **制作工作区**：面向编导和制作人员，以阶段节点画布完成素材绑定、脚本生成、图片/视频生产、校验、返工和交付。
- **管理控制台**：面向管理员和流程负责人，以标准后台完成工程治理、Workflow、NodeDefinition、Skill、Runner、资产规范、权限策略和审计管理。
- **统一真相层**：两端共同读取 WorkflowVersion、Project、NodeInstance、NodeRun、Artifact、Problem、Approval、Receipt；任何状态都不能只存在前端画布。

参考画布只用于确定以下交互语言：

- 节点内可以预览素材、Prompt、参数和产物；
- 端口和连线表达输入、输出和依赖；
- 生成节点可以直接触发运行；
- 分支可以直观表达图片、视频和 3D 等不同生产路线。

不沿用参考图的部分：

- 不把整集 23 个阶段和所有动态任务铺在一张无限画布；
- 不允许制作人员通过自由连线修改正式生产流程；
- 不把模型、Skill、校验、审批和治理信息全部塞进节点卡片；
- 不用一个“生成成功”替代 Validator、Gate 和业务审批。

## 2. 优化后的产品结构

### 2.1 全局工作区切换

顶部产品切换器只提供两个入口：

1. `制作工作区`
2. `管理控制台`

是否可见由角色权限决定。切换工作区时保留当前工程，但不保留未提交表单。

### 2.2 制作工作区一级导航

制作端收敛为四个入口：

| 入口 | 主要任务 | 是否使用画布 |
|---|---|---|
| 工程 | 创建、导入、切换、恢复工程 | 否 |
| 工作台 | 六阶段总览与当前阶段执行 | 是 |
| 资产 | 跨节点搜索、预览、版本、引用和替换 | 否 |
| 交付 | 业务审批、最终验收、导出和归档 | 否 |

运行和问题不再默认占用独立一级入口：

- 当前节点的运行和问题进入统一上下文检查器；
- 跨工程或批量检索才从管理控制台进入“运行与问题运营”；
- 制作端顶部保留全局问题计数和运行状态入口。

### 2.3 管理控制台一级导航

| 入口 | 主要任务 |
|---|---|
| 管理总览 | 活跃工程、运行、阻塞、审批、STALE、Runner 健康度 |
| 工程治理 | Manifest、目录、Owner、锁定、归档和证据包 |
| 工作流模板 | Frame、节点、边、Gate、版本、影响分析和发布 |
| 节点与 Skill | NodeDefinition、Skill 路由、Schema、权限声明和测试 |
| Runner 集群 | 能力、队列、心跳、日志、排空、迁移和停用 |
| 资产规范 | 资产角色、元数据 Schema、Hash、去重和血缘规则 |
| 权限与审批 | 角色、工程范围、写入根、工具审批和业务审批策略 |
| 运行与问题 | 跨工程查询 NodeRun、Problem、日志和证据 |
| 审计与收据 | 发布、审批、迁移、运行和治理动作的不可变记录 |

## 3. 制作端画布结构

### 3.1 从三级画布收敛为两级

旧方案的“工程总画布 → 阶段子画布 → 动态任务子画布”容易造成下钻过深。新方案只保留：

#### 第一级：工程阶段总览

- 显示 6 个 Frame，不显示全部 23 个阶段节点；
- 每个 Frame 只显示完成率、Gate、Problems、STALE 和合法下一步；
- 点击 Frame 进入当前阶段画布；
- 不在总览直接编辑 Prompt 或运行具体 Skill。

#### 第二级：单阶段执行画布

阶段内按照生产方向从左到右布局：

```text
素材 / 脚本
→ 配置 / Prompt
→ Skill 执行
→ 产物集合
→ Validator
→ Gate / Approval
```

ACTION、SUPPORT、S01–S19 等批量任务不再默认进入第三层画布，而是聚合为“任务集合节点”：

- 节点内显示缩略图或任务格；
- 支持网格、列表、仅异常三个视图；
- 点击单项后在右侧检查器查看完整内容；
- 只有复杂单项需要独立依赖图时，才使用临时聚焦视图，不形成永久第三层导航。

### 3.2 画布布局规则

- 默认使用自动布局，主链从左到右，辅助素材从上到下接入；
- 每个阶段控制在 5–9 个主节点；
- 超过 9 个时使用集合节点或可折叠 Group；
- 用户可以移动节点改善个人视图，但不能改变业务依赖；
- 选择节点后只高亮其输入、输出、校验和返工路径；
- 画布坐标、缩放和展开状态属于用户视图，不写入 WorkflowVersion。

## 4. 节点系统

### 4.1 节点家族收敛

制作端只出现七类节点：

| 节点 | 节点内主要信息 | 主要操作 |
|---|---|---|
| 素材 `MATERIAL` | 图片缩略图、脚本摘要、版本、批准状态 | 预览、绑定、替换 |
| 配置 `CONFIG` | Prompt 摘要、开放参数、约束锁 | 编辑、恢复默认 |
| 执行 `SKILL_RUN` | 实际 Skill、输入完整度、最近运行、预计成本 | 预检、运行、中断 |
| 产物 `ARTIFACT` | 图片格、脚本段、视频预览、覆盖率 | 查看、对比、下载 |
| 校验 `VALIDATOR` | 检查项、缺口、证据、版本 | 校验、查看问题 |
| 门禁 `GATE` | 放行条件、阻断原因、审批状态 | 查看条件、进入审批 |
| 人工任务 `HUMAN_TASK` | 指派人、截止时间、所需产物 | 完成、退回、重分配 |

RECEIPT、NodeRun、Problem 不再作为长期占据画布的主节点：

- Receipt 在检查器和运行记录中查看；
- NodeRun 是执行节点的运行实例；
- Problem 附着在产生它的节点上。

### 4.2 节点信息密度

每个节点支持三档显示：

1. **缩略态**：标题、状态、进度、端口；用于低缩放。
2. **标准态**：增加内容预览、输入输出数量和主操作；默认使用。
3. **展开态**：放大节点的图片格或参数区；同一时间只允许展开一个节点。

节点不展示完整日志、完整 JSON、全部 Hash 或全部审批历史。

### 4.3 图片、脚本和视频节点

#### 图片资产

- 素材节点内显示 1–4 张代表性缩略图；
- 图片集合节点显示镜号或任务号网格；
- 缺失项使用虚线占位并显示缺失原因；
- 点击缩略图后在检查器显示大图、元数据、来源、引用和关联脚本；
- 图片替换先计算影响，再写入新版本。

#### 生成脚本

- 节点内只显示 3–5 行摘要；
- 检查器提供“可读视图 / 原始 JSON / Prompt / 执行日志”；
- 点击镜号脚本块时同步选中对应图片，反向亦然；
- 修改脚本生成候选版本，不直接覆盖已批准版本。

#### 视频资产

- 节点内显示封面、时长、分辨率和生成状态；
- 检查器中播放、逐帧查看、查看 Prompt 和来源图片；
- 视频生成任务可以按镜号批量运行，但每个镜号拥有独立 NodeRun。

### 4.4 节点交互约定

| 操作 | 结果 |
|---|---|
| 单击节点 | 选中节点并打开检查器上次使用的标签 |
| 单击内容 | 打开检查器“内容”标签并定位对应项目 |
| 双击节点 | 聚焦并切换标准态/展开态 |
| 点击运行 | 打开执行预检，不直接创建 NodeRun |
| 右键节点 | 只显示与该节点和当前模式合法的操作 |
| 拖动端口 | 制作模式只允许绑定兼容素材；不能改变正式主链 |
| 点击错误徽标 | 打开检查器“问题”标签 |
| 点击版本徽标 | 打开检查器“版本”标签 |

## 5. 统一上下文检查器

右侧只保留一个检查器，标签固定为：

1. `内容`
2. `执行`
3. `问题`
4. `版本与血缘`

### 5.1 内容

- 图片、视频或文档的完整预览；
- 结构化生成脚本；
- 输入引用与来源；
- 下载、定位和对比。

### 5.2 执行

- NodeDefinition、WorkflowVersion 和实际 Skill 路由；
- 输入快照、允许写入根、预期输出和 Validator；
- Preflight 结果；
- 当前及历史 NodeRun、实时日志和工具审批。

### 5.3 问题

- Validator 证据、Problem ID、严重级别和影响范围；
- 合法修复动作；
- 重新校验和创建新 NodeRun；
- 禁止直接编辑 PASS / FAIL。

### 5.4 版本与血缘

- 当前版本、历史版本和 Hash；
- 输入到输出的血缘；
- Diff 和影响分析；
- “恢复”实际创建新版本，不覆盖历史。

检查器交互限制：

- 不叠加第二个检查器；
- 大图、长脚本和版本对比可以进入全屏任务层；
- 关闭后保留选中节点；
- 切换节点时保持当前标签，但内容自动刷新。

## 6. 执行、失败和审批闭环

### 6.1 执行

```text
运行节点
→ Preflight
→ 创建 NodeRun
→ Runner ACK
→ Skill 执行
→ 收集产物
→ Validator
→ 更新 NodeInstance
```

- Preflight 放在检查器“执行”标签，不使用大面积模态框；
- 只有危险命令的工具审批使用模态框；
- 运行中底部仅显示 40px 状态条，用户展开后才显示完整日志；
- NodeRun `SUCCEEDED` 不等于节点 `PASS`。

### 6.2 失败

```text
Validator FAIL
→ 创建 Problem
→ 检查器自动切换“问题”
→ 修复输入或配置
→ 新建 NodeRun / 重新校验
→ Validator 重新计算
```

旧产物和旧运行保留，不允许覆盖或手工关闭严重问题。

### 6.3 审批

- 工具审批：决定 Codex 是否可以执行某个命令；属于 NodeRun。
- 业务审批：决定内容是否被接受；属于 Artifact / Gate。
- 两种审批不共用界面、按钮和文案。
- 业务审批使用独立全屏任务层，支持预览、Diff、Validator 证据、批准、驳回和要求修改。

## 7. 管理端交互

### 7.1 管理端不使用无限画布的区域

管理总览、工程治理、Runner、资产规范、权限、运行检索和审计使用标准后台：

- 左侧模块导航；
- 顶部环境、搜索、告警和用户区；
- 中央列表/表格；
- 右侧详情检查器；
- 危险操作使用确认模态框。

### 7.2 唯一使用节点画布的管理模块

`工作流模板编辑器`使用画布，但与制作画布有明显模式差异：

- 顶部显示“模板草稿”而非工程状态；
- 左侧是受控节点库；
- 中央编辑 Frame、NodeDefinition、端口和 Gate；
- 右侧编辑 Schema、Skill 路由、权限声明和默认参数；
- 底部显示契约校验和测试结果；
- 保存只形成草稿，发布必须经过测试和影响分析。

### 7.3 Workflow 发布

```text
编辑草稿
→ Schema / 拓扑 / Gate 校验
→ Skill 沙盒测试
→ 计算受影响工程
→ 选择迁移策略
→ 二次确认
→ 发布新 WorkflowVersion
→ 生成审计收据
```

旧工程默认锁定旧版本；管理员不能静默批量迁移。

### 7.4 Skill 管理

```text
注册 SkillManifest
→ 声明输入输出与权限
→ 映射 NodeDefinition
→ 沙盒测试
→ 启用版本
→ 计算引用与影响
```

禁用 Skill 时：

- 不终止已经运行的 NodeRun；
- 阻止创建新的 NodeRun；
- 通知受影响 Workflow 和工程；
- 形成审计记录。

### 7.5 Runner 管理

- 查看在线、心跳、能力、队列、执行任务和允许目录；
- 异常 Runner 先“排空”，再迁移等待任务，最后停用；
- 已经开始且不可安全迁移的任务标记为 LOST 或等待人工处理；
- 管理员不能把未知结果直接标记成功。

### 7.6 权限与策略

- RBAC：管理员、流程负责人、制作人、审批人、观察者；
- 工程范围和写入根目录独立授权；
- 工具审批按风险、命令类型和目录范围配置；
- 业务审批按 Artifact 类型和 Gate 配置；
- 策略变更只影响之后创建的 NodeRun，并记录策略版本。

## 8. 制作端与管理端连接

| 管理端对象 | 制作端体现 |
|---|---|
| WorkflowVersion | 顶栏版本、阶段结构、NodeDefinition |
| SkillVersion | 执行检查器中的实际 Skill 路由 |
| RunnerPolicy | Preflight、Runner 分配和工具审批 |
| AssetSchema | 素材节点字段、缺失校验和引用规则 |
| ApprovalPolicy | Gate 条件和业务审批人 |
| AuditReceipt | 运行、审批、发布、迁移和交付证据 |

管理端变更到制作端的统一规则：

1. 变更必须生成新版本；
2. 发布前必须计算影响；
3. 已运行工程不自动迁移；
4. 上游内容变化时相关下游标记 STALE；
5. 任何迁移、重跑和重新审批都保留旧证据。

## 10. MVP 收敛建议

第一版优先实现：

- 工程导入和扫描映射；
- 六阶段总览；
- 一个真实阶段画布；
- 素材、配置、Skill、产物、Validator、Gate 六类核心节点；
- 图片格与生成脚本联动；
- 统一上下文检查器；
- 单节点 Preflight、NodeRun、Validator 和 Problem 闭环；
- 管理端 Workflow 只读、Skill 只读、Runner 状态和审计查询。

第二阶段再开放：

- Workflow 模板编辑与发布；
- Skill 注册与测试；
- Runner 排空和迁移；
- 权限与审批策略编辑；
- 全流程业务审批和最终交付。

## 11. 交互验收标准

- 用户不进入第三层永久子画布，也能完成批量分镜任务；
- 任意图片在两次操作内可看到大图、脚本和来源；
- 任意执行节点在一次选择后可看到实际 Skill、输入、输出、日志和问题；
- 同一时刻最多存在一个右侧检查器和一个必要模态框；
- 用户不能通过连线、右键或管理后台绕过 Gate；
- 管理员发布 Workflow 或 Skill 前必须看到受影响工程；
- 制作端可以识别当前使用的 Workflow、Skill、RunnerPolicy 和 ApprovalPolicy 版本；
- 所有运行、审批、发布、迁移和交付动作都有可导出的收据。
