# 交互与参考效果审查

## 审查范围

- 产品：柠萌旅行记 Agent 节点工作台
- 任务：从素材绑定到插件执行、产物预览、问题修复，以及管理端插件配置和 Skill 转换
- 视觉证据：`reference-canvas.png`
- 方案依据：`04-制作端与管理端整合优化交互方案.md`、`05-多资产与Skill插件化扩展方案.md`

## 用户目标与无障碍目标

制作人员需要在不离开阶段画布的情况下完成多资产绑定、插件配置、运行和产物检查；管理员需要安全地配置插件输入输出并把 Skill 转换为插件适配器。界面需要支持键盘焦点、非颜色状态提示和足够的点击目标。

## 参考效果的优势

1. 节点即操作单元：输入、参数、执行按钮和预览都在节点内。
2. 产物直观：图片和视频结果不需要进入二级页面才能判断。
3. 流程关系清晰：连线直接表达素材如何参与下游生成。
4. 局部配置高效：用户可以在画布上连续完成多个生产步骤。

## 主要风险

1. 原参考图缺少工程、阶段、问题、运行和管理导航，无法承载完整生产生命周期。
2. 长链不断横向扩展，在真实 23 阶段工程中会产生定位困难。
3. 节点内参数过多时，低缩放下文字不可读，高缩放下画布容量不足。
4. 单个素材节点会让多资产项目产生大量连线。
5. 生成成功、Validator、Gate 和业务审批在参考图中没有可靠区分。
6. 仅凭截图无法验证键盘顺序、焦点陷阱、屏幕阅读器名称和缩放回流。

## 重构决定

- 保留深色点阵画布、富内容节点、直接运行和产物预览。
- 增加六阶段导航，但不把 23 个阶段同时铺开。
- 多资产使用 AssetCollection 节点，一条类型化连接传递集合引用。
- 节点内保留高频操作；完整内容、执行、问题和版本使用单一检查器。
- 制作端和管理端共用顶部工作区切换器。
- 管理端使用标准后台；仅 Workflow 模板编辑需要节点画布。
- Skill 转插件必须经过分析、映射、测试和版本发布。

## 审查步骤

| 步骤 | 可见状态 | 健康度 |
|---|---|---|
| 1 | 参考画布与富节点 | 良好：直接操作强；缺少完整产品外壳 |
| 2 | 制作端阶段画布 | 良好：阶段和画布关系清楚 |
| 3 | 多资产添加 | 良好：批量、多选、角色和重复策略集中完成 |
| 4 | 图片与脚本预览 | 良好：图片和对应脚本保持同一上下文 |
| 5 | 执行预检与 NodeRun | 良好：运行前证据明确，状态可恢复 |
| 6 | Validator 问题修复 | 良好：不允许人工伪造 PASS |
| 7 | 插件输入输出配置 | 良好：Schema 与节点 UI 同步预览 |
| 8 | Skill 转插件向导 | 良好：事实、推断和人工确认被区分 |

## 无障碍风险与限制

- 状态均有文字标签，没有只依赖颜色。
- 主要按钮和表单使用原生可聚焦元素。
- 当前截图视口为桌面端，尚未针对窄屏做产品承诺。
- React Flow 节点的完整键盘拖动和屏幕阅读器路径仍需真实辅助技术测试。
- 字号与对比度为视觉检查结果，尚未进行自动 WCAG 对比度测量。
