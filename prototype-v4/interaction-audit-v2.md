# 柠萌旅行记 Agent 工作台交互复评（V2）

## 审计范围

- 产品表面：制作工作区、资产/脚本详情、缺漏修复、管理总览、插件配置、Skill → Plugin。
- 用户目标：在长链路脚本与视觉生产中及时发现缺漏，查看问题证据，用最小范围修复，并能追溯实际 Skill、输入资产和输出。
- 证据视口：1280 × 720，深色主题，EP01 / 分镜准备 / S13 缺失状态。

## 总体结论

原型的能力覆盖已经完整，但优化前更像“功能陈列式节点编辑器”：节点、Inspector、运行条都在，当前任务却没有成为第一视觉层级。对柠萌旅行记这种长流程、批量资产、AI 多次执行的场景，用户最需要的不是先理解整张图，而是立刻回答四个问题：哪里阻塞、证据是什么、只需重跑什么、修复后由谁复检。

优化后的主模型改为“任务导向工作区 + 无限画布 + 上下文 Inspector”。无限画布仍是流程真相，不再承担全部导航责任。

## 流程步骤与健康度

1. 进入 EP01 分镜准备 — 良好
   - 首屏展示当前阻塞“缺失 S13”、受影响 Gate、执行范围和修复动作。
   - 保留 S01–S19 图片预览，避免任务条取代资产可视性。

2. 查看多资产集合 — 良好
   - 节点内保留 4 张真实缩略图；批量添加支持本机、工程资产和节点产物。
   - 添加队列增加角色/场景/构图自动识别及重复 Hash 检查反馈。

3. 查看图片与生成脚本 — 良好
   - 同一 Inspector 中可切换“图片资产 / 对应脚本 / 前后镜”。
   - 结构化脚本展示画面、景别/运镜、台词和连续性约束。

4. 识别 S13 缺漏 — 良好
   - 当前目标条、输出集合、Validator 和底部最近运行形成四层一致状态。
   - 问题证据包含 Problem ID、来源 Run、覆盖率和影响 Gate。

5. 创建修复 NodeRun — 良好
   - 默认采用单镜修复；明确复用原 Run 输入快照，不改动 18 个已通过产物。
   - 预检显示仅消耗 1 个图像生成任务，结束后自动重跑覆盖 Validator。

6. 管理端查看平台状态 — 良好
   - 管理总览、工程、模板、Runner、权限和审计均有对应内容视图，不再是静态导航壳。
   - 管理事件回链工程、节点、NodeRun 与 Artifact。

7. 配置插件输入输出 — 良好
   - 保留输入 Schema、输出契约和节点实时预览。
   - 多资产通过 `AssetCollection` 和 typed port 进入插件契约。

8. Skill 转 Plugin — 良好
   - 分析结果区分 SKILL.md 明确声明与 AI 推断。
   - 两项推断未确认时，“下一步”禁用；确认后才允许进入 Operations 和输入输出映射。

## 仍需真实工程验证

- 键盘拖动画布、节点端口连线和焦点顺序需要完整无鼠标测试。
- 真实 100+ 资产上传时的虚拟列表、缩略图解码、重复检测性能尚未验证。
- Runner 断线、部分成功、重试失败、审批驳回等异常状态仍使用模拟数据。
- 目前是前端原型，没有持久化、实际 Codex 连接、插件执行与权限沙盒。

## 最高优先级后续建议

1. 用真实 `project-manifest.json`、NodeDefinition、NodeRun 和 ProblemReceipt 替换 mock 数据。
2. 将阶段轨道、画布节点、Inspector 和管理总览统一绑定同一状态源，避免状态漂移。
3. 为 AssetCollection 引入虚拟化网格、角色筛选、Hash 去重与批量版本策略。
4. 为 Skill 转换器增加来源行号、引用证据和适配器 diff，提升审核可信度。
